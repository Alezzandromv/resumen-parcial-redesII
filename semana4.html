MÓDULO 7 · SRWE
DHCPv4 — Asignación Dinámica de Direcciones IP
⚡ ¿Qué es DHCP? En lugar de configurar manualmente la IP de cada computadora, DHCP hace que el router (o servidor) la asigne automáticamente. El cliente "pide prestada" una dirección por un tiempo determinado llamado arrendamiento (lease). Cuando el arrendamiento vence, el cliente la renueva o pide una nueva.
¿Cómo funciona? — El proceso de 4 pasos (DORA)
ℹ Cuando una PC se conecta a la red por primera vez, realiza estos 4 pasos para obtener una dirección IP. Imagina que tu PC está "recién llegada" y necesita que le asignen un lugar (IP) en la red.
PASO 1
DHCPDISCOVER
La PC grita a toda la red: "¡Hay algún servidor DHCP? Necesito una IP!" — Envía un broadcast porque aún no sabe la IP del servidor.
PASO 2
DHCPOFFER
El servidor responde: "¡Aquí estoy! Te ofrezco esta IP: 192.168.1.10" — Le propone una dirección disponible de su pool.
PASO 3
DHCPREQUEST
La PC confirma: "¡Acepto la IP que me ofreció el servidor X!" — Lo manda a broadcast para que otros servidores también sepan cuál eligió.
PASO 4
DHCPACK
El servidor confirma: "¡Trato hecho! La IP es tuya por X días" — Envía la IP, máscara, gateway y DNS definitivos.
🔄 Renovar el arrendamiento: Antes de que venza el tiempo del "préstamo" de IP, la PC solo necesita 2 pasos: envía un DHCPREQUEST directamente al servidor, y el servidor responde con un DHCPACK. Sin el proceso de 4 pasos porque ya se conocen.
Tipos de VLANs — qué información entrega DHCP

🌐 Dirección IP

La dirección que identifica a la PC en la red. Ejemplo: 192.168.10.15. Sin esta, la PC no puede comunicarse con nadie en la red.

obligatorio

🎭 Máscara de subred

Define qué parte de la IP es la "red" y qué parte identifica al dispositivo. Ejemplo: 255.255.255.0 (o /24). El DHCP siempre la entrega junto a la IP.

obligatorio

🚪 Default Gateway

La "puerta de salida" hacia otras redes e internet. Normalmente es la IP del router. Sin gateway, la PC solo puede hablar con dispositivos de su misma red local.

default-router

🔍 Servidor DNS

El "directorio telefónico" que convierte nombres de dominio (google.com) en IPs. DHCP puede configurar uno o más servidores DNS automáticamente.

dns-server

⏱ Tiempo de arrendamiento

Cuánto tiempo "presta" la IP al cliente. Por defecto suele ser de 24 horas a 1 semana. Al vencer, el cliente renueva o pide una nueva IP.

lease days/hours

🏷 Nombre de dominio

El dominio de la organización, por ejemplo "empresa.local". Permite resolver nombres dentro de la red interna sin escribir la IP completa.

domain-name
Configurar DHCP en un Router Cisco (IOS)
ℹ Un router Cisco puede actuar como servidor DHCP directamente, sin necesidad de un servidor dedicado. Esto es ideal para oficinas pequeñas (SOHO). La configuración tiene 3 pasos clave: excluir IPs reservadas → crear el pool → configurar el pool.
IOS CLI — Configurar servidor DHCPv4 completo
===================================================== PASO 1: Excluir IPs que NO deben asignarse dinámicamente → Siempre excluye las IPs del router, servidores, impresoras y cualquier dispositivo con IP fija ===================================================== R1(config)# ip dhcp excluded-address 192.168.10.1 192.168.10.9 → Excluye el rango .1 a .9 (para router, gateways, etc.) R1(config)# ip dhcp excluded-address 192.168.10.254 → También se puede excluir una sola IP ===================================================== PASO 2: Crear y nombrar el pool (grupo de IPs disponibles) ===================================================== R1(config)# ip dhcp pool LAN-OFICINA → Entra al modo de configuración DHCP ===================================================== PASO 3: Configurar el pool con la info que recibirán los clientes ===================================================== R1(dhcp-config)# network 192.168.10.0 255.255.255.0 → Define el rango de red del que se tomarán IPs R1(dhcp-config)# default-router 192.168.10.1 → Gateway que recibirán los clientes (IP del router) R1(dhcp-config)# dns-server 8.8.8.8 8.8.4.4 → Servidores DNS (aquí usamos Google como ejemplo) R1(dhcp-config)# domain-name empresa.local → Dominio interno de la empresa (opcional) R1(dhcp-config)# lease 2 → Arrendamiento de 2 días (por defecto es 1 día) R1(dhcp-config)# end --- Un segundo pool para otra VLAN/subred en el mismo router --- R1(config)# ip dhcp excluded-address 192.168.20.1 192.168.20.9 R1(config)# ip dhcp pool LAN-VENTAS R1(dhcp-config)# network 192.168.20.0 255.255.255.0 R1(dhcp-config)# default-router 192.168.20.1 R1(dhcp-config)# dns-server 8.8.8.8

El gran problema: ¿qué pasa si el servidor DHCP está en otra red?
⚠ Problema: El DHCPDISCOVER es un broadcast. Los routers, por diseño, NO reenvían broadcasts entre redes. Si el servidor DHCP está en otra subred, los clientes nunca lo encontrarán. Solución: DHCP Relay Agent con el comando ip helper-address.
Sin Relay — El problema
  • PC en red 192.168.10.0 envía broadcast DHCPDISCOVER
  • El router R1 recibe el broadcast en su interfaz local
  • R1 descarta el broadcast — no lo reenvía al servidor DHCP
  • El servidor DHCP está en 192.168.11.0 y nunca lo recibe
  • La PC no obtiene IP → sin conectividad
Con Relay — La solución
  • Se configura ip helper-address en la interfaz del router
  • R1 recibe el broadcast DHCPDISCOVER de la PC
  • R1 lo convierte en unicast y lo reenvía al servidor DHCP
  • El servidor DHCP responde y R1 retransmite la respuesta
  • La PC obtiene su IP correctamente ✓
IOS CLI — Configurar DHCP Relay (ip helper-address)
Situación: PCs en 192.168.10.0/24, servidor DHCP en 192.168.11.6 Se configura en la interfaz que DA LA CARA a los clientes DHCP R1(config)# interface gigabitethernet 0/0/0 → Esta es la interfaz conectada a los clientes (LAN) R1(config-if)# ip helper-address 192.168.11.6 → Dirección IP del servidor DHCP real → Ahora R1 retransmitirá los DHCPDISCOVER al servidor R1(config-if)# end --- Verificar que el helper-address está configurado --- R1# show ip interface g0/0/0 GigabitEthernet0/0/0 is up, line protocol is up ... Helper address is 192.168.11.6 ← confirma que está activo --- NOTA: ip helper-address también retransmite estos servicios UDP: --- Puerto 37 → Tiempo Puerto 67 → DHCP/BOOTP servidor Puerto 53 → DNS Puerto 68 → DHCP/BOOTP cliente Puerto 49 → TACACS Puerto 69 → TFTP Puerto 137 → NetBIOS nombres Puerto 138 → NetBIOS datagramas
Configurar un Router como Cliente DHCP
ℹ En redes domésticas y SOHO, el router en sí necesita obtener su IP de Internet del ISP. En este caso el router actúa como cliente DHCP, no como servidor. Es un solo comando en la interfaz que apunta al ISP.
IOS CLI — Router que pide IP al ISP via DHCP
La interfaz WAN del router (la que apunta al ISP) pide IP por DHCP R1(config)# interface gigabitethernet 0/0/1 → Interfaz WAN (conectada al módem del ISP) R1(config-if)# ip address dhcp → El router pedirá su IP al ISP como un cliente DHCP normal R1(config-if)# no shutdown --- Verificar que el ISP asignó una IP --- R1# show ip interface g0/0/1 GigabitEthernet0/0/1 is up, line protocol is up Internet address is 209.165.201.12/27 ← IP asignada por el ISP Broadcast address is 209.165.201.31 ...
MÓDULO 9 · SRWE
FHRP / HSRP — Redundancia de Gateway (No perder la salida a Internet)
⚡ El problema que resuelven: Cada PC tiene configurado un solo gateway predeterminado (el router). Si ese router falla, toda la red pierde acceso a Internet... incluso si hay otro router conectado. FHRP/HSRP crean un "router virtual" que combina dos routers reales en uno lógico.
La solución: El Router Virtual
Sin FHRP — Punto único de falla
  • Todas las PCs tienen gateway = 192.168.1.1 (Router A)
  • El Router A falla ✗
  • Hay un Router B disponible pero las PCs no saben de él
  • Las PCs siguen enviando al gateway .1 que no responde
  • Toda la red pierde conectividad externa hasta que alguien reconfigure cada PC
Con FHRP — Alta disponibilidad
  • Los Routers A y B se configuran como grupo HSRP
  • Comparten una IP virtual (VIP): 192.168.1.254
  • Las PCs tienen gateway = 192.168.1.254 (el router virtual)
  • Router A es el activo, Router B es el standby (reserva)
  • Si A falla → B asume el rol automáticamente sin tocar nada ✓
Opciones FHRP disponibles
ProtocoloTipoDescripción
HSRPCISCO Propietario de Cisco Hot Standby Router Protocol. El más usado en entornos Cisco. Un router activo, uno en standby. Cuando falla el activo, el standby toma control automáticamente.
HSRP for IPv6CISCO Propietario de Cisco Versión de HSRP para redes IPv6. Mismo principio pero adaptado al protocolo de nueva generación.
VRRPv2OPEN Estándar IEEE Virtual Router Redundancy Protocol. Similar a HSRP pero es estándar abierto, funciona con cualquier fabricante.
GLBPCISCO Propietario de Cisco Gateway Load Balancing Protocol. Más avanzado: permite que múltiples routers compartan activamente el tráfico (balanceo de carga), no solo tener uno activo y uno de reserva.
HSRP — Cómo funciona en detalle

🏆 Router Activo

El que realmente reenvía el tráfico de los clientes. Responde a la IP y MAC virtual. Solo puede haber uno activo por grupo HSRP.

reenvía tráfico real

💤 Router Standby (Reserva)

Escucha los "hellos" del activo. Si deja de recibirlos en 10 segundos, asume automáticamente el rol de activo sin intervención humana.

listo para tomar el control

🔮 IP Virtual (VIP)

La IP que configuran las PCs como gateway. No pertenece al router activo ni al standby, pertenece al grupo virtual. Siempre está disponible.

standby ip <VIP>

💌 Mensajes Hello

El router activo envía mensajes "Hello" cada 3 segundos diciendo "Sigo vivo". Si el standby no recibe hellos en 10 segundos, asume que el activo falló y toma el control.

cada 3 seg / espera 10 seg

📊 Prioridad HSRP

Determina quién será el router activo. El de mayor prioridad gana. Por defecto es 100. Rango: 0–255. Si hay empate, gana el de mayor IP.

standby priority <0-255>

⚡ Preempt (Intento)

Si un router con mayor prioridad vuelve a estar online, ¿debería "recuperar" el rol de activo? Solo si tiene activado preempt. Sin esta opción, el que sea activo lo sigue siendo aunque llegue uno de más prioridad.

standby preempt
Estados HSRP — El ciclo de vida de un router en el grupo
Initial
Estado inicial al arrancar
→
Learn
Esperando conocer la IP virtual
→
Listen
Conoce la VIP, escucha hellos pero no es ni activo ni standby
→
Speak
Envía hellos y participa en la elección del activo
→
Standby
Candidato a activo. Monitorea al activo actual
→
Active
Reenvía tráfico. Es el gateway real
Configurar HSRP — Comandos Completos
IOS CLI — Configurar HSRP en R1 (activo) y R2 (standby)
======================================================== ESCENARIO: R1: IP real 192.168.10.2/24 → será el router ACTIVO R2: IP real 192.168.10.3/24 → será el router STANDBY IP Virtual (VIP): 192.168.10.1 ← esta es la que usan las PCs Grupo HSRP: 1 (número identificador del grupo, puede ser 0-255) ======================================================== === CONFIGURACIÓN EN R1 (Router Activo) === R1(config)# interface gigabitethernet 0/0/1 → Interfaz hacia la LAN de los clientes R1(config-if)# standby version 2 → Usar HSRPv2 (recomendado — más grupos, mejor para IPv6) R1(config-if)# standby 1 ip 192.168.10.1 → Grupo 1, IP Virtual = 192.168.10.1 ← lo que configuran las PCs R1(config-if)# standby 1 priority 150 → Prioridad 150 > 100 (default de R2) → R1 ganará la elección R1(config-if)# standby 1 preempt → Si R1 cae y vuelve, recuperará automáticamente el rol activo === CONFIGURACIÓN EN R2 (Router Standby) === R2(config)# interface gigabitethernet 0/0/1 R2(config-if)# standby version 2 R2(config-if)# standby 1 ip 192.168.10.1 → ¡Misma IP Virtual y mismo grupo! Así se unen al mismo grupo HSRP R2(config-if)# standby 1 priority 100 → Prioridad 100 (menor que R1) → R2 será el standby R2(config-if)# standby 1 preempt → Opcional en el standby, pero buena práctica activarlo

PARTE 1 Configurar R1 como Servidor DHCP para dos subredes

PARTE 3 Configurar R1 como Cliente DHCP hacia el ISP
R1 — Interfaz WAN pide IP al ISP
La interfaz g0/0/2 de R1 está conectada al router del ISP R1(config)# interface gigabitethernet 0/0/2 R1(config-if)# ip address dhcp → R1 actuará como cliente DHCP en esta interfaz R1(config-if)# no shutdown R1(config-if)# end --- Verificar que el ISP asignó una IP a R1 --- R1# show ip interface g0/0/2 Internet address is 209.165.201.x/27 ← IP asignada por el ISP

LAB 9.3.3
Guía de Configuración HSRP
Router Activo · Router Standby · Verificación failover
▼

📋 Enunciado del Lab

  • Objetivo: Configurar HSRP para proporcionar un gateway predeterminado redundante a los hosts de la LAN
  • Paso 1: Configurar un router activo HSRP (R1 con prioridad alta)
  • Paso 2: Configurar un router en espera HSRP (R3 como standby)
  • Paso 3: Verificar la operación HSRP (incluyendo failover cuando cae el activo)
Configurar HSRP entre R1 y R3 para que las PCs tengan un gateway virtual 192.168.1.254 que siga funcionando si alguno de los routers físicos falla. Probar que el failover es automático y transparente.
PASO 1 Configurar R1 como Router Activo HSRP
R1 — Prioridad alta → será el Activo
Topología: R1 (192.168.1.1) ─── R3 (192.168.1.3) Ambos conectados a la misma LAN 192.168.1.0/24 IP Virtual HSRP: 192.168.1.254 ← lo que configuran las PCs R1(config)# interface gigabitethernet 0/0/1 → Interfaz de R1 conectada a la LAN de los clientes R1(config-if)# standby version 2 → Usar HSRPv2 (recomendado, soporta hasta 4096 grupos) R1(config-if)# standby 1 ip 192.168.1.254 → Grupo HSRP número 1 → IP Virtual = 192.168.1.254 (esta IP la ponen las PCs como gateway) R1(config-if)# standby 1 priority 150 → Prioridad 150 > default 100 → R1 gana la elección = activo R1(config-if)# standby 1 preempt → Si R1 cae y vuelve a levantarse, recupera el rol de activo → Sin preempt, el que sea activo seguiría siéndolo aunque R1 volviera R1(config-if)# end --- Verificar estado de R1 en HSRP --- R1# show standby brief Interface Grp Pri P State Active Standby Virtual IP Gi0/0/1 1 150 P Active local 192.168.1.3 192.168.1.254 → State = Active ✓ P = preempt activo ✓
PASO 2 Configurar R3 como Router Standby HSRP
R3 — Prioridad default 100 → será el Standby
R3 usa la misma IP virtual y el mismo grupo (1) → se une al grupo HSRP R3(config)# interface gigabitethernet 0/0/1 R3(config-if)# standby version 2 R3(config-if)# standby 1 ip 192.168.1.254 → ¡Misma VIP que R1! Así se sabe que forman el mismo grupo virtual R3(config-if)# standby 1 priority 100 → Prioridad 100 < 150 (R1) → R3 será el standby automáticamente R3(config-if)# standby 1 preempt R3(config-if)# end --- Verificar estado de R3 en HSRP --- R3# show standby brief Interface Grp Pri P State Active Standby Virtual IP Gi0/0/1 1 100 P Standby 192.168.1.1 local 192.168.1.254 → State = Standby ✓ Active = R1 (192.168.1.1) ✓
PASO 3 Verificar HSRP y probar el Failover
Verificación completa y prueba de failover automático
--- Ver estado detallado del grupo HSRP --- R1# show standby GigabitEthernet0/0/1 - Group 1 (version 2) State is Active Virtual IP address is 192.168.1.254 ← IP que usan las PCs Active virtual MAC address is 0000.0c9f.f001 Hello time 3 sec, hold time 10 sec ← Hello cada 3s, timeout 10s Preemption enabled Active router is local Standby router is 192.168.1.3 ← R3 listo como reserva Priority 150 (configured 150) --- Confirmar que las PCs tienen la IP virtual como gateway --- PC-A Gateway: 192.168.1.254 ← IP Virtual, no la IP real del router === PRUEBA DE FAILOVER === Paso 1: Apagar la interfaz de R1 (simula falla del router activo) R1(config)# interface g0/0/1 R1(config-if)# shutdown → R3 deja de recibir hellos de R1 → Después de 10 segundos, R3 asume el rol de ACTIVO automáticamente Paso 2: Verificar en R3 que asumió el rol activo R3# show standby brief Interface Grp Pri P State Active Standby Virtual IP Gi0/0/1 1 100 P Active local unknown 192.168.1.254 → State cambió a Active ✓ (antes era Standby) Paso 3: Las PCs siguen funcionando sin cambiar nada PC-A> ping 192.168.1.254 → ¡Sigue respondiendo! (ahora responde R3) PC-A> ping 8.8.8.8 → Internet también sigue funcionando Paso 4: Volver a activar R1 — debe recuperar el rol activo (preempt) R1(config-if)# no shutdown → R1 vuelve, detecta que tiene mayor prioridad y hace preempt → R1 vuelve a ser el activo, R3 vuelve a standby R1# show standby brief Interface Grp Pri P State Active Standby Virtual IP Gi0/0/1 1 150 P Active local 192.168.1.3 192.168.1.254 → R1 volvió a ser Active ✓ R1# copy running-config startup-config R3# copy running-config startup-config

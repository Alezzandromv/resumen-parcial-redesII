MÓDULO 3 · SRWE
VLANs
⚡ Concepto clave: Una VLAN es una red lógica dentro de un switch físico. Cada VLAN es un dominio de broadcast separado. Sin un router o switch capa 3, dispositivos en distintas VLANs NO pueden comunicarse.
Tipos de VLAN

🔒 VLAN 1 — Predeterminada

Todos los puertos del switch pertenecen a VLAN 1 por defecto. También es la VLAN nativa y de administración predeterminada. No se puede eliminar ni renombrar. Mala práctica usarla para administración.

no se puede borrar

📊 VLAN de Datos

Para tráfico de usuarios: correo, web, archivos. VLAN 1 es la predeterminada porque todos los puertos se asignan a ella. Se recomienda crear VLANs separadas por departamento.

🔇 VLAN Nativa

En enlaces troncales 802.1Q, las tramas de la VLAN nativa se envían sin etiqueta. Ambos extremos del trunk deben tener la misma VLAN nativa. Por defecto es VLAN 1.

untagged en trunk

🛠 VLAN de Administración

Usada para tráfico SSH/Telnet al dispositivo. Normalmente es el SVI del switch capa 2. No debe mezclar tráfico de usuarios finales.

📞 VLAN de Voz

VoIP requiere VLAN separada: QoS garantizado, latencia <150ms, ancho de banda asegurado. Los teléfonos Cisco usan CDP para aprender su VLAN de voz. El teléfono etiqueta su propio tráfico (CoS).

QoS obligatorio

📏 Rangos de VLAN

Rango normal: 1–1005 (PYMEs). Guardadas en vlan.dat en flash.
Rango extendido: 1006–4095 (proveedores). En running-config. Requiere VTP modo transparente.
Reservadas: 1002–1005 (legacy Token Ring/FDDI).

Trunking — IEEE 802.1Q
ℹ Un trunk (enlace troncal) es un enlace punto a punto entre switches (o switch-router) que transporta tráfico de múltiples VLANs simultáneamente. Usa etiquetas 802.1Q de 4 bytes para identificar a qué VLAN pertenece cada trama.
IOS CLI — Configurar y verificar trunks 802.1Q
--- CONFIGURAR TRUNK --- S1(config)# interface fastethernet 0/1 S1(config-if)# switchport mode trunk → Fuerza modo trunk permanente S1(config-if)# switchport trunk native vlan 99 → Cambia VLAN nativa (NO usar VLAN 1) S1(config-if)# switchport trunk allowed vlan 10,20,30,99 → Solo estas VLANs pasan --- VERIFICAR TRUNK --- S1# show interfaces trunk → Todos los trunks activos S1# show interfaces fa0/1 switchport → Detalles del puerto (modo, encap, VLAN nativa) S1# show interfaces fa0/1 trunk → VLANs permitidas en ese trunk --- RESTABLECER TRUNK A DEFAULTS --- S1(config-if)# no switchport trunk native vlan → Vuelve nativa a VLAN 1 S1(config-if)# no switchport trunk allowed vlan → Permite todas las VLANs --- CONVERTIR TRUNK A ACCESO --- S1(config-if)# switchport mode access → Deshabilita el trunk
DTP — Dynamic Trunking Protocol
⚠ DTP es propietario de Cisco. En switches Catalyst 2960/2950, el modo por defecto es dynamic auto. Cisco recomienda configurar los puertos como trunk o access estático y desactivar DTP con switchport nonegotiate.

--- MODOS DTP --- S1(config-if)# switchport mode dynamic auto → Default: solo trunk si vecino lo pide S1(config-if)# switchport mode dynamic desirable → Busca activamente formar trunk S1(config-if)# switchport mode trunk → Trunk estático (recomendado) S1(config-if)# switchport mode access → Acceso estático (recomendado) --- DESACTIVAR DTP (mejor práctica) --- S1(config-if)# switchport nonegotiate → No envía tramas DTP --- VERIFICAR DTP --- S1# show dtp interface fastethernet 0/1 → Modo DTP actual S1# show interfaces fa0/1 switchport → Modo admin y operacional
MÓDULO 4 · SRWE
Enrutamiento Inter-VLAN
⚡ Dispositivos en distintas VLANs necesitan un dispositivo de Capa 3 para comunicarse. Hay 3 métodos: heredado (obsoleto), Router-on-a-Stick, y Switch de Capa 3 con SVIs (el más moderno y escalable).
3 Métodos de Inter-VLAN Routing
Router-on-a-Stick
  • Una sola interfaz física del router
  • Se divide en subinterfaces virtuales
  • Cada subinterfaz = una VLAN
  • Encapsulación 802.1Q en cada subinterfaz
  • El puerto del switch conectado = trunk
  • Solución para redes pequeñas/medianas
  • Límite práctico: ~50 VLANs
Switch Capa 3 + SVIs
  • Switch multilayer (ej: Catalyst 3650)
  • Una SVI por cada VLAN enrutable
  • Routing por hardware (ASIC) — muy rápido
  • Sin enlace externo switch-router
  • Soporta EtherChannel para más ancho de banda
  • Latencia mínima — todo en el mismo chasis
  • Requiere ip routing habilitado
Router-on-a-Stick — Configuración Completa
IOS CLI — Subinterfaces en el router + trunk en el switch
=== EN EL SWITCH S1 === --- Crear VLANs --- S1(config)# vlan 10 S1(config-vlan)# name Faculty S1(config)# vlan 20 S1(config-vlan)# name Students S1(config)# vlan 99 S1(config-vlan)# name Native --- Puerto de acceso para PC en VLAN 10 --- S1(config)# interface fa0/6 S1(config-if)# switchport mode access S1(config-if)# switchport access vlan 10 --- Puerto trunk hacia el router --- S1(config)# interface fa0/5 S1(config-if)# switchport mode trunk S1(config-if)# switchport trunk native vlan 99 S1(config-if)# switchport trunk allowed vlan 10,20,99 === EN EL ROUTER R1 === --- Habilitar la interfaz física (sin IP aquí) --- R1(config)# interface g0/0/1 R1(config-if)# no shutdown → ¡Crítico! Activa la interfaz R1(config-if)# exit --- Subinterfaz para VLAN 10 --- R1(config)# interface g0/0/1.10 → .10 = número de subinterfaz (convenio = VLAN ID) R1(config-subif)# encapsulation dot1q 10 → Esta subinterfaz = VLAN 10 R1(config-subif)# ip address 192.168.10.1 255.255.255.0 → Default GW para VLAN 10 --- Subinterfaz para VLAN 20 --- R1(config)# interface g0/0/1.20 R1(config-subif)# encapsulation dot1q 20 R1(config-subif)# ip address 192.168.20.1 255.255.255.0 --- Subinterfaz para VLAN nativa 99 --- R1(config)# interface g0/0/1.99 R1(config-subif)# encapsulation dot1q 99 native → Palabra "native" para VLAN nativa R1(config-subif)# ip address 192.168.99.1 255.255.255.0 --- Verificar routing --- R1# show ip route R1# show ip interface brief R1# show interfaces g0/0/1.10
Switch Capa 3 — Inter-VLAN con SVIs
IOS CLI — Switch multicapa (ej: Catalyst 3650) con ip routing
=== EN EL SWITCH DE CAPA 3 (D1) === --- Paso 1: Crear VLANs --- D1(config)# vlan 10 D1(config-vlan)# name Faculty D1(config)# vlan 20 D1(config-vlan)# name Students --- Paso 2: Crear SVIs (una por VLAN) --- D1(config)# interface vlan 10 D1(config-if)# ip address 192.168.10.1 255.255.255.0 → Default GW VLAN 10 D1(config-if)# no shutdown D1(config)# interface vlan 20 D1(config-if)# ip address 192.168.20.1 255.255.255.0 → Default GW VLAN 20 D1(config-if)# no shutdown --- Paso 3: Puertos de acceso --- D1(config)# interface g1/0/6 D1(config-if)# switchport mode access D1(config-if)# switchport access vlan 10 --- Paso 4: HABILITAR ROUTING (¡obligatorio!) --- D1(config)# ip routing → Sin este comando NO hay inter-VLAN routing --- Puerto enrutado hacia router externo --- D1(config)# interface g1/0/1 D1(config-if)# no switchport → Convierte puerto L2 en L3 (routed port) D1(config-if)# ip address 10.10.10.2 255.255.255.0 --- Verificar --- D1# show ip route D1# show interfaces vlan 10 D1# show ip interface brief

Glosario Clave — Semana 2
Término / ComandoSignificado
VLANRed lógica dentro del switch. Separa dominios de broadcast sin necesidad de hardware adicional.
Trunk / Enlace TroncalPuerto que transporta tráfico etiquetado de múltiples VLANs entre switches o switch-router.
802.1QEstándar IEEE para etiquetado de VLANs en tramas Ethernet. Añade 4 bytes a la trama.
VLAN nativaVLAN cuyo tráfico viaja sin etiqueta por el trunk. Debe ser la misma en ambos extremos.
DTPDynamic Trunking Protocol — protocolo Cisco para negociar trunks automáticamente.
Router-on-a-StickRouter con subinterfaces 802.1Q conectado a un trunk del switch. Enruta entre VLANs.
SVISwitch Virtual Interface — interfaz lógica en switch capa 3 que actúa como gateway de VLAN.
ip routingComando que habilita el routing en un switch multicapa. Sin él, no hay inter-VLAN routing.
no switchportConvierte un puerto de switch L2 en puerto enrutado L3 (para conectar a otro dispositivo L3).
encapsulation dot1q <id>Asocia una subinterfaz de router a una VLAN específica para recibir su tráfico etiquetado.
CoSClass of Service — QoS de Capa 2 para priorizar tráfico de voz sobre datos.
VTPVLAN Trunking Protocol — sincroniza VLANs entre switches. VLANs extendidas requieren modo transparente.
